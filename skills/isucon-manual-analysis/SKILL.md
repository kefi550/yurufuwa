# ISUCON マニュアル解析

manual.md を起点に、スコア計算・失格/減点条件・制約を整理する。
**manual.md 以外の文書名は決め打ちしない。** manual.md 内で参照されている
文書があればそれを追加で読みに行く、という一段の間接参照として扱う。

## 前提条件

- manual.md のパスを必須引数として受け取る。渡されていなければ、まずパスを尋ねる。
- manual.md 以外の資料(アプリ仕様書、API定義、ネットワーク構成図など)のファイル名や有無は競技ごとに異なる。この時点では何も仮定しない。

## 手順

1. manual.md を読み込む。
2. 以下を抽出する:
   - スコアの計算式(基準点、減点、加点要素の内訳)
   - クリティカルエラー/失格条件(スコアが0になる、あるいは競技失格になる条件)
   - その他の減点ルール(レスポンス内容の検証、タイムアウト、禁止行為など)
   - ベンチマーク実行に関する制約(実行時間、初期化の扱い、同時実行の可否など)
3. manual.md の本文中から、**他の文書への参照**を探す
   (「詳細は◯◯を参照」「別紙◯◯」「APIについては◯◯」のような文言、
   ファイル名らしき文字列やURL/リンクなど)。
4. 見つかった参照ごとに:
   - manual.md と同じディレクトリ、リポジトリのルートなど、ローカルに
     存在するか確認する。
   - 存在すれば読み込み、手順2の整理に反映する
     (例: アプリケーション固有の仕様書ならAPI一覧やレスポンス仕様、
     減点に関わる検証ルールなどを追加で拾う)。
   - 存在しなければ「manual.md 内で `<文書名>` への参照が見つかったが
     ローカルには無い」とユーザーに伝え、必要なら提供を求める
     (ここで処理を止めずに、見つかったものだけで整理を進めてよい)。
5. 手順2〜4の内容を、日本語で構造化して出力する(下記フォーマット)。
   この出力は、ログ解析skill・コード解析skillなどが「manual.mdの要点」
   として利用する共通の参照情報になる想定。

## 出力フォーマット

- **スコア計算式**: 箇条書きで要素と重みを整理
- **クリティカルエラー/失格条件**: 具体的な条件と、それぞれのスコアへの影響
- **その他の減点ルール**
- **ベンチマーク実行に関する制約**
- **参照文書**: manual.md内で見つかった参照文書ごとに「文書名/URL・
  ローカルで発見できたか・反映した内容の要約」を一覧化

## 既知の罠

- manual.md自体が大会ごとに構成・見出しが変わるため、固定のセクション名で
  パースしようとせず、内容から都度読み取る。
- 参照文書が見つからない場合でも処理を止めない(部分的な情報でも整理を進め、
  不足分だけをユーザーに伝える)。
- ベンチマーカーのソースコードは読まない(既存メモリ方針:
  ベンチのソースは読まず、manual.md やそこから発見された文書のみを根拠にする)。
